# Hive 表权限核对与申请

> 使用当前 Cursor 会话登录的公司 SSO 账号（不要写死姓名/工号）。  
> 查表入口：`http://factory.data.ke.com/tableSearch`  
> 申请落地页：`http://auth-bigdata.ke.com/approvalApplyAuth?...`（hive表权限申请：为个人）  
> 表清单来源：优先用户指定；否则读 [get-data](../get-data/SKILL.md) 的 `tables.md` / `tables/*.md`。  
> 字段/表详情检索见 [get-data/docs/internal-table-search.md](../get-data/docs/internal-table-search.md)。

## 何时触发

- 用户要求核对某张/一批表是否有**查询**、**开发**权限
- 写 SQL / 取数前发现无权限，需要申请
- 用户说「帮我申请表权限」「数据工厂权限」「离线开发 / 数据查询」

## 硬规则

1. **只走前端页面**（Cursor 内置浏览器）。工厂 API 需要 `ts/sign`，不要走未签名接口。
2. **不要索要账号密码**。停在 `login.ke.com` 时，提示用户在内置浏览器完成 SSO，登录后再继续。
3. **一步一步**：先出核对结果，再确认是否申请；有效期与申请理由未指定时先问用户。
4. **遇到阻塞就问**：搜不到表、页面写「请勿申请」、提交被拦、审批单异常。
5. **不要重复申请已有权限**：蓝勾（`check-circle`）= 已有，跳过。
6. 描述含「请勿申请」或标记无效的表，**默认跳过**，除非用户明确要求。

## 权限图标读法（数据工厂表卡片）

在搜索结果卡片右侧 `.right-btn-wraper` / `.icon_wrap`：

| 文案 | 有权限 | 无权限（可点） |
|------|--------|----------------|
| 查询 | 蓝色 `check-circle` | 灰色 `plus-square` / `sound` |
| 开发 | 蓝色 `check-circle` | 灰色 `plus-square` / `sound` |

权限点映射（申请单上显示）：

| 工厂文案 | 申请单权限点 |
|----------|--------------|
| 查询 | 数据查询 |
| 开发 | 离线开发 |

点击无权限图标 = **加入待申请列表**（通常无弹窗，看「待申请」角标数字增加）。

## 标准流程

### 1. 确定表清单

- 用户给表名 → 用用户清单
- 否则从 get-data 字典收集表名（可按用户要求剔除 P2C：`rpt_p2c_*`、Roomie/IM、交易工具 ODS 等）
- 搜索用**裸表名**或 `layer.table` 均可；卡片标题以裸表名匹配更稳

### 2. 逐表核对

1. 打开 `http://factory.data.ke.com/tableSearch`
2. 在搜索框填入表名，回车/搜索
3. 读对应卡片的查询/开发图标状态
4. 记录：`有查询 / 有开发 / 缺查询 / 缺开发 / 搜不到 / 跳过(请勿申请)`

搜不到（0 结果）：记为待确认，问用户是否改名/下线，**不要硬申请**。

### 3. 把缺权限加入待申请

对每张缺权限的表，只点**缺失**的那几个图标（查询和/或开发）。

可用页面内辅助函数思路（`Runtime.evaluate`）：

```js
// 在当前搜索结果中，按表名点击缺失权限图标
// perms: ['查询'] | ['开发'] | ['查询','开发']
// 定位：.right-btn-wraper → 向上找含表名的卡片 → .icon_wrap + .icon-text
// 仅当图标不是 check-circle 时 click
```

全部加完后，确认「待申请」角标数量与预期一致。

### 4. 提交申请单

1. 点 **待申请列表**
2. 核对资源与权限点无误 → **下一步**
3. 进入大数据权限页（`auth-bigdata.ke.com`），确认：
   - 申请类型：hive表权限申请：为个人
   - 申请者：个人 / 当前 SSO 登录用户（不要填别人的姓名或工号）
   - 资源列表与权限点正确
4. 填 **权限有效期**、**申请理由**（未指定则先问）
5. 点 **提交**
6. 成功文案类似：`提交成功，审批进度可前往权限申请-审批中的申请或 企微-流程中心 处查看`

填写技巧：a11y ref 易 stale；可用 CDP 对 `textarea` 赋值并 `dispatchEvent('input'/'change')`，再点提交。提交后用 `document.body.innerText` 确认「提交成功」，不要只信旧 snapshot。

### 5. 默认填写（用户未另指定时再确认）

| 字段 | 常用值 |
|------|--------|
| 权限有效期 | 一年(365)天 |
| 申请理由 | 产品经理数据分析使用，烦请协助进行权限审批 |

## 输出格式

核对阶段先给表：

```markdown
| 表 | 查询 | 开发 | 动作 |
|---|---|---|---|
| `xxx` | 有 | 缺 | 待申请开发 |
| `yyy` | 有 | 有 | 跳过 |
| `zzz` | — | — | 搜不到/请勿申请 |
```

申请提交后再回报：有效期、理由、表清单、成功与否、如何查审批进度。

## 常见坑

- **API**：`tableSearch` 等接口有签名，浏览器里未登录会话外调用会失败 → 坚持页面操作。
- **点图标无弹窗**：正常，目标是加待申请列表。
- **提交被 smart-mode 拦截**：请用户在内置浏览器亲手点一次「提交」，或批准本次自动提交。
- **多标签页**：申请页可能新开 tab；操作前用 `browser_tabs` 确认当前 viewId。
- **P2C / 敏感表**：用户要求剔除时不要纳入申请。

## 与 get-data 的关系

- 查字段/口径 → 用 get-data  
- 查有没有权限、缺了去申请 → 用本 skill  
- 表结构检索登录方式与本 skill 相同（内置浏览器 + SSO）
