# 内部表信息查询

> 公司内部表信息入口：`http://factory.data.ke.com/tableSearch`
>
> 访问会跳转到 `login.ke.com` SSO 登录页。当前观察到支持 Link、A+、D+、Studio、企微扫码登录。
> 使用当前 Cursor 会话登录的公司 SSO 账号（不要写死姓名/工号）。

## 什么时候使用

写 Hive SQL 前，如果遇到以下情况，先查内部表信息网站，再写 SQL：

- 表不在本 Skill 的 `tables.md` 或 `tables/` 明细文件中
- 不确定字段名、字段类型、字段含义
- 不确定表的分区字段、更新频率、生命周期
- 历史 SQL 与当前表结构冲突
- 需要确认字段是否可用于 JOIN、聚合或过滤

## 查询顺序

1. 先查本地 Skill 字典：`tables.md` -> `tables/*.md`
2. 本地没有或不确定时，打开 `http://factory.data.ke.com/tableSearch`
3. 如果停在 `login.ke.com`，在前端提示用户：**“请在 Cursor 内置浏览器中完成公司 SSO 登录，登录后告诉我继续。”** 不要索要账号密码，不要猜测或绕过登录
4. 登录后用完整表名搜索，例如 `rpt.rpt_log_bi_user_behivor_detail_flow_di`
5. 记录以下信息：
   - 表中文名 / 业务说明
   - 所属层级：rpt / olap / ods / dw / dim
   - 分区字段，尤其是否为 `pt` 以及是否还有 `site`、`dp`、`evt_type` 等复合分区
   - 字段名、字段类型、字段含义
   - 数据更新时间 / 数据负责人 / 业务负责人 / 权限说明 / 血缘说明（如页面提供）
6. 将确认后的稳定信息沉淀回 `tables/*.md`

### 表查询页

搜索框支持输入：

- 表 id
- 表名
- 表中文名
- 描述
- 负责人
- 多类型组合搜索（用空格隔开）

高级搜索可按以下条件筛选：

- 表类型
- 集群
- 数据层级
- 数据库
- 数据负责人
- 业务审批人
- 分类
- 标签
- 只看核心表
- 隐藏无效表

搜索结果卡片会展示：

| 信息 | 用途 |
|------|------|
| 表名 / 表中文名 | 确认是否为目标表 |
| 标签 | 如高价值、事实表、行级权限、任务/天、保留近365天数据 |
| 数据负责人 / 业务负责人 | 字段不清楚或权限问题时找谁 |
| 表类型 / 集群 / 空间 | 确认 Hive、公共集群、所属团队 |
| 字段数量 | 粗略判断表复杂度 |
| 更新时间 | 判断数据是否还在更新 |
| 描述 | 判断业务用途 |
| 右侧查询 / 开发图标 | 蓝勾=已有权限；灰加号/喇叭=无权限，可点进待申请 |

**核对或申请查询/开发权限**：走配套 skill [hive-table-permission](../../hive-table-permission/SKILL.md)，不要猜权限状态。

### 表详情页

详情页常见 Tab：

| Tab | 能看什么 | 写 SQL 时怎么用 |
|-----|----------|----------------|
| 基本信息 | 表名、中文名、集群、表类型、数据层级、数据库、安全等级、存储量、是否分区、创建/修改信息、数据负责人、业务负责人、所属空间、权限包、标签、描述、生命周期 | 判断表是否适合用、是否有权限、是否高成本、找负责人 |
| 字段信息 | 字段名称、字段中文名、描述、枚举值、数据类型、是否加密、安全级别、单位、是否可空、默认值、是否主键、是否分区字段 | 确认字段名/类型/含义/分区字段，禁止凭记忆写字段 |
| 分区信息 | 分区创建日期、分区名搜索、分区路径、存储量、分区创建时间、查看分区数据 | 确认最新分区是否产出、复合分区写法、数据量 |
| 变更历史 | 表/字段变更记录 | 字段口径突变或 SQL 失效时先查 |
| 调度任务 | 任务周期、有效期、触发方式、引擎、重试、并发、超时、队列、状态、需求方、依赖任务、依赖数据、失败通知人 | 判断数据产出时间、上游依赖、任务失败联系人 |
| 权限规则 | 审批流程规则、行级权限规则 | 查询失败或行级权限表时先看 |
| 数据血缘 | 上下游血缘 | 改 ETL / 查来源时用 |
| 全链路血缘 | 更完整链路血缘 | 影响面分析 |
| 版本列表 | 表版本 | 回看历史版本 |
| 价值评估 | 表价值/热度 | 选表优先级 |

## 使用原则

- 内部网站是字段结构的权威来源；历史 SQL 是实际用法参考。
- 若内部网站与历史 SQL 不一致，先按内部网站确认字段，再检查历史 SQL 是否过期。
- 不要凭记忆补字段名。字段不存在或含义不明确时，先停下来查。
- 不要把临时猜测写入 `tables/*.md`；只沉淀已确认、可复用的信息。

## 无法访问时

如果当前环境无法打开内部网站：

- 明确告诉用户“内部表检索网站当前不可访问/需要内网或登录”
- 如果只是未登录，先唤起 Cursor 内置浏览器，并提示用户在前端完成 SSO 登录
- 使用历史 SQL 与已有字典先给候选方案
- 对字段名和分区规则标注“待内部表检索确认”
